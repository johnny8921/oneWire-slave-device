# oneWire-slave-device

Мост между физическими датчиками DS18B20 и внешним мастером 1-Wire на базе **NodeMCU Amica ESP8266**. Устройство опрашивает шесть независимых входов, создаёт на общей выходной шине копии подключённых датчиков с исходными ROM-адресами и показывает температуры на OLED.

В репозитории также есть программа для платы с MicroPython, которая циклически сканирует выходную шину моста и печатает температуры.

## Возможности

- Шесть входов, по одному физическому DS18B20 на каждом.
- Копия датчика появляется на D2 после проверки ROM и первого корректного измерения.
- Полный 64-битный ROM-адрес копии совпадает с адресом физического датчика.
- При ошибке чтения или отключении датчика копия удаляется с выходной шины. Повторный поиск запускается через 500 мс.
- На OLED сохраняются последние показания и адреса до 16 разных датчиков, подключавшихся после запуска. При перезагрузке история очищается.
- Датчик с ошибкой остаётся в таблице OLED с мигающей ячейкой и статусом `ERROR` в персональной карточке.
- Wi-Fi отключён.

## Подключение NodeMCU Amica

Названия `D0`–`D7` относятся к маркировке платы. Номера GPIO приведены отдельно.

| Назначение | Контакт платы | GPIO |
| --- | --- | --- |
| Вход датчика 1 | D1 | 5 |
| Вход датчика 2 | D0 | 16 |
| Вход датчика 3 | D3 | 0 |
| Вход датчика 4 | D4 | 2 |
| Вход датчика 5 | D7 | 13 |
| Вход датчика 6 | SD3 | 10 |
| Общий выход к внешнему мастеру | D2 | 4 |
| OLED SDA | D6 | 12 |
| OLED SCL | D5 | 14 |

Для каждого физического датчика подключите `VDD` к `3V3`, `GND` к `GND`, а `DQ` к соответствующему входу. Между каждым входом DQ и 3V3 нужен отдельный резистор **4,7 кОм**. Используется трёхпроводное питание.

```text
NodeMCU 3V3 ----+---------------- VDD датчика
               |
             4,7 кОм
               |
Вход DQ -------+---------------- DQ датчика
NodeMCU GND -------------------- GND датчика
```

Внешний мастер подключается к D2 и общей земле. Выходная шина D2 требует своей подтяжки к 3,3 В. Входы датчиков и D2 электрически разделены, каждый подключается по таблице.

OLED подключается четырьмя проводами — `GND`, питание `3V3`, `SDA` к D6 и `SCL` к D5. Текущий драйвер рассчитан на **SH1106 128×64**. При запуске проверяются адреса `0x3C` и `0x3D`.

D3/GPIO0 и D4/GPIO2 должны иметь высокий уровень при обычной загрузке ESP8266. Шестой вход SD3/GPIO10 доступен при работе флеш-памяти в режиме **DIO**. Прошивка проверяет этот режим и отключает шестой вход, если выбран другой. Программное мигание встроенным светодиодом в рабочем режиме отключено, поскольку D4 занят датчиком.

Справочная информация о загрузочных выводах и режиме памяти приведена в документации производителей. [Режимы загрузки ESP8266](https://docs.espressif.com/projects/esptool/en/latest/esp8266/advanced-topics/boot-mode-selection.html) · [NodeMCU Hardware FAQ](https://nodemcu.readthedocs.io/en/1.5.4.1-final/hardware-faq/)

## Сборка в Arduino IDE

1. Добавьте адрес пакета плат в настройки Arduino IDE.

   ```text
   https://arduino.esp8266.com/stable/package_esp8266com_index.json
   ```

2. Установите пакет **esp8266 by ESP8266 Community**. Проект собирался с версией **3.1.2**.
3. Через менеджер библиотек установите **OneWire 2.3.8** и **U8g2 2.36.19**.
4. Откройте `OneWireTemperature/OneWireTemperature.ino` вместе с остальной папкой скетча.
5. Выберите **NodeMCU 1.0 (ESP-12E Module)**, CPU **80 MHz**, Flash Mode **DIO** и порт платы. При разработке использовался **COM10**.
6. Загрузите скетч и откройте монитор порта на **115200 бод**.

Нужные файлы OneWireHub с локальными изменениями уже включены в `OneWireTemperature/src/OneWireHub`. Для диагностики используются сообщения о сбросе, ROM Search и командах DS18B20.

## OLED

Первые страницы показывают таблицы по десять датчиков. После таблиц следуют персональные карточки всех запомненных датчиков. Страницы переключаются каждые **5 секунд**, индикатор в правом верхнем углу имеет формат `01/07`.

На карточке отображаются номер датчика, крупная температура до сотых с `°C`, полный ROM-адрес и нижняя строка со статусом слева, пином по центру и временем последнего успешного измерения справа.

```text
SENSOR 01  02/07

    24.50°C

28xxxxxxxxxxxxxx

OK     D1    00s
```

Для отключённого датчика показываются последнее значение, последний пин и статус `ERROR`. Его ячейка в таблице мигает с периодом около секунды. Номер датчика соответствует порядку первого обнаружения после загрузки. Два знака после запятой задают формат отображения, разрешение самого DS18B20 определяется его конфигурацией.

## Мастер на MicroPython

На плату-мастер с модулями `onewire` и `ds18x20` скопируйте **оба файла** из папки `master` в корень файловой системы.

- `main.py` автоматически запускает цикл после старта платы.
- `scan.py` содержит инициализацию шины и поиск с паузой между проходами.

По умолчанию используется **GPIO12 платы-мастера**. Соедините его с D2 ESP8266 и объедините земли. При другой распиновке измените `ONEWIRE_GPIO` в `main.py`.

Каждый цикл заново ищет датчики, отбирает DS18B20 с корректным CRC ROM, запрашивает преобразование, ждёт 750 мс и выводит полный адрес и температуру. После цикла следует пауза 1000 мс. Ошибка чтения отдельного датчика выводится в консоль.

```text
DS18B20 found: 1
28xxxxxxxxxxxxxx: 24.50 C
```

Поиск использует внутренний метод `_search_rom` драйвера MicroPython с паузой **50 мс**. Этот вариант применяется после проверки на стенде, где непрерывный `scan()` находил только часть эмулируемых датчиков. При смене версии драйвера доступность внутреннего метода нужно проверить.

## Поведение и ограничения

- На каждом физическом входе поддерживается один DS18B20 семейства `0x28`. Для обнаружения используется команда Read ROM.
- Выходной датчик отдаёт последнее успешное измерение. Команда преобразования от внешнего мастера не запускает синхронное измерение на физическом входе.
- Копируется ROM-адрес и температура. Настройки разрешения, пороги тревог и EEPROM физического датчика через мост не передаются.
- Реестр OLED хранит до 16 уникальных ROM-адресов за сеанс. После заполнения реестра подключение нового адреса требует перезагрузки.
- Обработка входных шин и OLED чередуется с опросом OneWireHub. Паузы при обслуживании физических шин могут влиять на обмен с внешним мастером. Одновременная работа всех шести физических входов требует проверки на конкретном стенде.
